# UGV Task 2 — ROS 2 Simulation

A custom four-wheel Unmanned Ground Vehicle (UGV) developed and simulated using **ROS 2 Humble**, **Gazebo Classic**, **RViz2**, **URDF/Xacro**, and **ros2_control**.

This project demonstrates the complete workflow of creating a custom robot model, visualizing it in RViz2, spawning it in Gazebo, controlling it using `ros2_control` and `diff_drive_controller`, and operating it using keyboard teleoperation.

---

## Features

- Custom four-wheel UGV model
- URDF and Xacro robot description
- Four continuous wheel joints
- Visual, collision, and inertial properties
- RViz2 visualization
- Gazebo Classic simulation
- ROS 2 `ros2_control` integration
- `gazebo_ros2_control`
- `joint_state_broadcaster`
- `diff_drive_controller`
- Keyboard teleoperation using `teleop_twist_keyboard`
- Robot State Publisher and TF
- Custom C++ ROS 2 controller for RViz visualization
- Git and GitHub version control

## UGV Specifications

The robot consists of a rectangular chassis and four wheels.

| Parameter | Value |
|---|---:|
| Body length | 0.8 m |
| Body width | 0.5 m |
| Body height | 0.2 m |
| Wheel radius | 0.12 m |
| Wheel width | 0.08 m |
| Wheel separation | 0.58 m |
| Number of wheels | 4 |
| Wheel joint type | Continuous |

### Wheel Joints

The four wheel joints are:

- `front_left_wheel_joint`
- `front_right_wheel_joint`
- `rear_left_wheel_joint`
- `rear_right_wheel_joint`

## ROS 2 Architecture

### RViz2

The RViz visualization uses the following communication flow:

    teleop_twist_keyboard
              │
              │ /cmd_vel
              ▼
       ugv_controller
              │
              │ /joint_states
              ▼
    robot_state_publisher
              │
              │ /tf
              ▼
            RViz2

The custom C++ `ugv_controller` converts the commanded linear and angular velocity into left and right wheel velocities and publishes the corresponding joint states.

---

## Gazebo Architecture

For Gazebo, the robot uses `ros2_control` and `diff_drive_controller`.

    teleop_twist_keyboard
              │
              │ /cmd_vel
              ▼
    /diff_drive_controller/cmd_vel_unstamped
              │
              ▼
      diff_drive_controller
              │
              ▼
         ros2_control
              │
              ▼
          Wheel joints
              │
              ▼
            Gazebo

The Gazebo simulation uses:

- `gazebo_ros2_control`
- `joint_state_broadcaster`
- `diff_drive_controller`

The custom C++ `ugv_controller` is used for the RViz visualization setup and is not used to control the Gazebo robot.

Enter the workspace:

    cd ~/task2_ws

    colcon build

Source the workspace:

## Gazebo Simulation

First build and source the workspace:

    cd ~/task2_ws
    source /opt/ros/humble/setup.bash
    source install/setup.bash

Start Gazebo:

    ros2 launch ugv gazebo.launch.py

The launch file starts:

1. Gazebo Classic
2. `robot_state_publisher`
3. The UGV model
4. `gazebo_ros2_control`
5. `joint_state_broadcaster`
6. `diff_drive_controller`

The UGV is automatically spawned into Gazebo.

## Keyboard Teleoperation

The teleoperation node should be started from a **separate terminal**.

Open another terminal and run:

    source /opt/ros/humble/setup.bash
    source ~/task2_ws/install/setup.bash

Then start keyboard teleoperation:

    ros2 run teleop_twist_keyboard teleop_twist_keyboard \
      --ros-args \
      -r /cmd_vel:=/diff_drive_controller/cmd_vel_unstamped

Make sure the teleoperation terminal has keyboard focus.

### Teleoperation Controls

| Key | Action |
|---|---|
| `i` | Move forward |
| `,` | Move backward |
| `j` | Turn left |
| `l` | Turn right |
| `k` | Stop |
| `u` | Forward + left |
| `o` | Forward + right |
| `m` | Backward + left |
| `.` | Backward + right |

The available controls are also displayed by `teleop_twist_keyboard` when it starts.

## Checking the Robot Description

To validate the URDF:

    check_urdf src/ugv/urdf/ugv.urdf

For the Xacro file, first convert it to URDF:

    xacro src/ugv/urdf/ugv.urdf.xacro > /tmp/ugv.urdf

Then validate:

    check_urdf /tmp/ugv.urdf

A successful validation should report that the robot was successfully parsed.

## Testing the Differential Drive Controller

The controller can also be tested without keyboard teleoperation.

With Gazebo running:

    ros2 topic pub --rate 10 \
      /diff_drive_controller/cmd_vel_unstamped \
      geometry_msgs/msg/Twist \
      "{linear: {x: 0.3}, angular: {z: 0.0}}"

The UGV should move forward in Gazebo.

To stop it:

    ros2 topic pub --once \
      /diff_drive_controller/cmd_vel_unstamped \
      geometry_msgs/msg/Twist \
      "{linear: {x: 0.0}, angular: {z: 0.0}}"

## RViz and Gazebo Launch Files

The project contains two different launch files for two different purposes.

### RViz

    ros2 launch ugv display.launch.py

This uses the custom C++ controller to publish joint states for visualization.

### Gazebo

    ros2 launch ugv gazebo.launch.py

This uses `ros2_control` and `diff_drive_controller` to control the simulated robot.

**Do not launch both at the same time for normal operation**, because they use different mechanisms for controlling and publishing the wheel states.

## Troubleshooting

### Package Not Found

If you see:

    Package 'ugv' not found

source the workspace:

    source ~/task2_ws/install/setup.bash

If necessary, rebuild:

    cd ~/task2_ws
    colcon build
    source install/setup.bash

---

### Gazebo Starts but the Robot Does Not Move

Check the controllers:

    ros2 control list_controllers

You should see:

    joint_state_broadcaster
    diff_drive_controller

Then check the command topic:

    ros2 topic info /diff_drive_controller/cmd_vel_unstamped

The controller should have a subscription to this topic.

---

### Teleoperation Does Not Work

Make sure the teleoperation terminal has keyboard focus.

Start it using:

    ros2 run teleop_twist_keyboard teleop_twist_keyboard \
      --ros-args \
      -r /cmd_vel:=/diff_drive_controller/cmd_vel_unstamped

The remapping is required because the teleoperation node normally publishes:

    /cmd_vel

while the differential-drive controller listens to:

    /diff_drive_controller/cmd_vel_unstamped
